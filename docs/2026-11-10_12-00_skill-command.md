# wtm — `skill` and `skill install`

**Date:** 2026-11-10

## Problem

An AI agent asked to work with wtm (say, to write a `post_create.sh`) knows
nothing about it: the commands, the `.wtm/` layout or the `WTM_*` variables.

## Change

- `wtm skill` prints `internal/cli/skill.md`, a description of wtm written
  for agents. It follows the README but drops install/build and the TUI keys,
  and adds what an agent needs: don't open the TUI, use `list --json`, pass
  `--yes` to delete only once the user agrees. It needs no repository.
- `wtm skill install <agent>` writes `internal/cli/skill_install.md` to
  `<agent's skills dir>/wtm/SKILL.md`. That file holds only the front matter
  agents match on and an instruction to run `wtm skill`, so the installed
  copy never goes stale. `--dir` installs into any other skills directory.
- Both files are compiled into the binary with `go:embed`.
- Known agents: claude, codex (`~/.agents/skills`), copilot, cursor, gemini
  and opencode. `CLAUDE_CONFIG_DIR` and `XDG_CONFIG_HOME` are followed.
- `hook.Env.Vars()` now builds the `WTM_*` list, so a test can check that
  `skill.md` documents each one, along with every command and flag.
