# wtm — `post_delete.sh`

**Date:** 2026-11-11

## Problem

`post_create.sh` can set things up outside the new worktree (containers, a
database, a symlink), but nothing cleaned them up when the worktree was
deleted.

## Change

- `.wtm/post_delete.sh` runs after each successful delete, from the TUI or
  `wtm delete`. `wtm delete --no-hook` skips it.

| Decision | Choice |
|----------|--------|
| When it runs | After the delete, to match `post_create.sh` and its name. The worktree's directory and branch are already gone |
| Where it runs | The directory wtm runs in, since the worktree no longer exists |
| Variables | The same `WTM_*` set as `post_create.sh`. `WTM_BASE_BRANCH` is set but empty, so a value in wtm's own environment can't leak in, and `WTM_BRANCH` is empty for a detached worktree |
| Failure | The worktree stays deleted; wtm reports "the worktree was deleted, but .wtm/post_delete.sh failed" |
| Several at once (TUI) | The script runs straight after each delete, before the next one starts, so each run's output can be read on its own. Failures are listed after any worktrees that weren't deleted |
| `wtm prune` | Doesn't run it: pruning forgets worktrees whose directories are already gone, and wtm doesn't know their names |

## Code

- `hook.PostCreate` is now `hook.Script`, made by `NewPostCreate` or
  `NewPostDelete`; they differ only in the working directory.
- `config.PostDeleteName` and `config.PostDeleteScript` mirror the create
  ones.
- TUI: `deleteStepMsg` carries the hook after a successful delete. It's run
  with `tea.Exec`, and its `postDeleteDoneMsg` moves on to the next worktree.
  `pauseOnFailure` takes the script's name for its message.
- The README and `wtm skill` document both scripts with one table of
  variables.
