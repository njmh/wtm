# wtm — command line

**Date:** 2026-10-23

## Goal

Make wtm a hybrid TUI/CLI: `wtm` still opens the TUI, and `wtm <command>`
runs one action and exits. Every TUI action gets a command, with a help
screen.

## Commands

```
wtm                                              open the TUI
wtm list [--json]                         (ls)   list worktrees
wtm create <name> [-b base] [--no-hook]   (new)  create worktree + branch
wtm delete <worktree> [-y]                (rm)   delete worktree, directory, branch
wtm rename <worktree> <new-name>          (mv)   rename directory and branch
wtm prune                                        git worktree prune
wtm help | --help | --version | completion <shell>
```

## Layout

```
main.go                 calls cli.Execute and prints its error
internal/cli/
├── root.go             root command (runs the TUI), loadRepo, usage errors, version
├── list.go             table and --json output
├── create.go           create + post_create.sh
├── delete.go           delete + confirmation prompt
├── rename.go
├── prune.go
└── complete.go         shell completion of worktrees and branches
```

Imports still only point one way:

```
main ──► cli
cli  ──► config, git, hook, tui
tui  ──► config, git, hook
```

## Decisions

| Question | Decision |
|----------|----------|
| CLI library | Cobra, the most common Go CLI framework. It provides the help screens, "did you mean" suggestions and completion scripts for bash, zsh, fish and PowerShell |
| Command names | Verbs matching the TUI menu (create, delete, rename, prune), plus list. Short aliases (`ls`, `new`, `rm`, `mv`) follow Unix habits |
| No-argument run | The root command's `RunE` launches the TUI, so `wtm` behaves exactly as before |
| Naming a worktree | `git.Repo.Find` accepts the name shown by `wtm list`, a path (shell completion adds a trailing `/`, which is ignored) or a branch name |
| Delete confirmation | Asks `[y/N]` on stderr, as git does. `-y`/`--yes` skips it. If stdin isn't a terminal it refuses without `--yes`, so a script can never hang on, or silently answer, the prompt |
| List output | An aligned table like the TUI, or `--json` for scripts. JSON uses its own struct with explicit field tags so its field names don't change if `git.Worktree` does |
| Errors | Cobra's own printing is silenced, and `main` prints `wtm: <error>` and exits 1. Usage mistakes end with `Run 'wtm <cmd> --help' for usage.` instead of dumping the whole help |
| Hook in the CLI | `post_create.sh` gets the process's stdin, stdout and stderr. `--no-hook` skips it, e.g. in CI |
| "Press Enter" pause | The pause after a failing hook keeps its output from being hidden when the TUI redraws. A CLI returns to the shell, so the pause moved out of `hook` into `tui` (`pauseOnFailure`) |
| Shared logic | Moved into `git` so both front ends use one copy: `Find`, `Branches`, `CheckChangeable` (the "main worktree can't be deleted" message) and `Worktree.BranchLabel`/`Tags`/`ShortHead` |
| Testability | Each command is built by a `newXxxCmd()` function rather than package-level variables, so tests build a fresh tree, set its args and stdin, and capture its output. `isTerminal` is a variable so tests can simulate a terminal |
| `--version` | Read from `debug.ReadBuildInfo`, so `go install …@v1.2.0` reports `v1.2.0` with no build flags |

## Verification

- `gofmt -l .` and `go vet ./...` are clean, and `go test ./...` passes. New
  tests: `git` (`TestFind`, `TestBranches`, `TestCheckChangeable`), `cli`
  (list, usage errors, create and its hook, delete with and without a prompt,
  rename, prune, completion) and `tui` (`TestHookPausesOnFailure`).
- Ran the real binary in a container repo with `worktree_path = "trees"`
  and a `post_create.sh`: create (with the hook, with `--base`, with
  `--no-hook`), list, rename, and the delete prompt answered in tmux.
  Piped delete without `--yes` refused with exit 1.
- `wtm` with no arguments still opens the TUI, and a failing hook there
  still waits for Enter and then shows the error dialog.
